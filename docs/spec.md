ユーザーが指定した仕様書セクション `$ARGUMENTS` を `docs/spec.md` から抽出し、その内容に基づいて以降の実装提案 / コード生成を行ってください。

## 手順

1. `docs/spec.md` を読み込む (`Read` ツール)
2. セクション番号 `$ARGUMENTS` を `## X. ...` または `### X.Y ...` または `#### X.Y.Z ...` として grep で位置特定
3. 該当セクションの冒頭から、**次の同レベルまたは上位レベルの見出し**までを抽出
   - 例: `§4.5` を要求された場合 → `### 4.5 ...` から `### 4.6 ...` または `## 5. ...` の直前まで
4. 抽出した内容を以下の形式で要約:

   ```
   ## 仕様書 §X.Y 要約
   <主要な要件 / 規約を 3-5 行で>

   ## 実装上の留意点
   1. <留意点 1>
   2. <留意点 2>
   3. <留意点 3>

   ## 関連セクション
   <相互参照されている §X.Y のリスト>
   ```

5. その後、ユーザーが続けて指示する実装タスク (component 作成 / 型定義 / API 実装等) の **直接の context** として使う

## 例

ユーザー: `/spec §4.5`
→ §4.5 数値表現規約を抽出し、smallest unit string / bigint / decimal.js / API boundary 検証 / 禁止事項 / 適用外 を構造化要約

ユーザー: `/spec §8.5`
→ §8.5 実行確認モーダル + Warning area の表示規約 を抽出

ユーザー: `/spec §11.7`
→ §11.7 AgentPlan を抽出し、status 遷移 10 種 / plan_id ↔ simulation_id の関係 / selected_action のセット規約 を整理

## 注意

- 仕様書は v0.2.15 (3300+ 行)。**全文を context に入れない**。常に該当セクションのみ抽出
- 抽出後の実装提案は CLAUDE.md §11 のチェックリスト + §9 整合性チェックを self-apply
- セクション番号が見つからない場合は、最も近い見出しを 3 つ提示して再指定を求める
